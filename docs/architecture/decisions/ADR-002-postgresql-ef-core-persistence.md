# ADR-002: Use PostgreSQL with EF Core for Initial Persistence

Status: Accepted
Date: 2026-08-30

## Context

MedResearch needs durable storage for research questions, research runs, study metadata, and extracted evidence. The project is expected to evolve toward scientific source retrieval, traceable citations, background workers, and possibly vector search later.

The repository is still a layered monolith. Persistence should not leak into Domain, and no AI functionality is being introduced in this decision.

## Decision

Use PostgreSQL as the primary relational database and EF Core with the Npgsql provider as the first persistence implementation. Keep `MedResearchDbContext` and all entity mappings in `MedResearch.Infrastructure`. Use explicit `IEntityTypeConfiguration<T>` mapping classes.

Store domain enum states as strings to keep database rows readable and avoid magic integer meanings. Use GUID primary keys generated by the domain constructors. Add indexes for DOI, PMID, and research run status/created-time queries because those match expected lookup paths.

Use Testcontainers for integration tests so persistence behavior is checked against real PostgreSQL semantics. Do not replace those tests with EF Core InMemory when PostgreSQL behavior matters.

## Alternatives Considered

- EF Core InMemory for integration tests: rejected because it does not enforce PostgreSQL relational behavior, type mapping, or FK semantics.
- SQLite for integration tests: rejected because it still differs from PostgreSQL in provider behavior and SQL semantics.
- Dapper-first persistence: deferred because EF Core gives migrations, mapping, and change tracking with less early project code.
- Adding pgvector now: rejected because no vector search use case exists yet.

## Consequences

The project now has a concrete relational schema and migration workflow. Infrastructure owns persistence, while Domain remains EF-free. Integration tests require a reachable Docker engine to run fully, because they start a disposable PostgreSQL container. Docker Compose can run the API and PostgreSQL locally with development-only defaults.
